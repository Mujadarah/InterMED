## 24. Architecture Notes for Codex

1. InterMED must be local-first.
2. Local encrypted storage is the default source of truth.
3. iCloud sync is optional.
4. Face ID, Touch ID, PIN/password are optional.
5. No account is required in v1.
6. Appwrite is future-only.
7. Google Sign-In and Sign in with Apple are future-only.
8. Google Drive, OneDrive and Dropbox should first be supported through encrypted file export/import where possible.
9. Dedicated cloud SDKs should only be added when automatic provider-specific backup/sync is implemented.
10. Clinical rules, medication data, evidence and AI providers must be abstracted behind protocols/interfaces.
11. AI may assist with extraction, summarization and conversation, but high-risk clinical decisions must not depend solely on an LLM.
12. All clinically meaningful outputs should be traceable to their source, rule version and evidence version.
13. Patient identity fields should remain optional.
14. Never log patient data to analytics or technical logs.
15. The project must remain modular and migration-safe for future database, sync, backend and account changes.


## 25. Suggested Prompt for Codex

Read this file together with all InterMED project specification files before modifying code.

Treat Apple first-party frameworks as the preferred implementation unless there is a strong technical reason to introduce a third-party dependency.

Use the day-one stack above for the initial implementation.

Do not add future-only SDKs or backend services until the corresponding milestone explicitly requires them.

Keep storage, authentication, cloud sync, medication data, guideline data, drug interactions and AI providers abstracted behind protocols so they can be replaced later without changing the clinical domain layer.

Preserve the local-first architecture and clinical-safety constraints at all times.
