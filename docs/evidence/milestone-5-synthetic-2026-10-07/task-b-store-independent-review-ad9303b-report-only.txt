## 4. Residual findings (minor; not blocking)

- **N1 — MINOR, fail-closed over-restriction:** the flat real SDK methods
  `containsAny` and `containsAll` (`appwrite/sdk-for-web` `src/query.ts`) fall
  through to the unknown-method refusal (`appwrite-store.js:297-299`) and are
  named neither in the method tables (`:36-74`) nor in the refusal note
  (`:297-298`, `store-final-api.md:239-241`, which lists only composite and
  distance/vector/geo). Impact: a legitimate flat array-attribute filter is
  refused pre-fetch — no wrong data, no reflection, recorded usage
  (`equal`/`orderDesc`/`limit`/`cursorAfter`/`select`) unaffected. Fix options:
  add a bounded `attribute` + scalar-list family for them, or name them in the
  documented refusal note.
- **N2 — NIT, hostile-stream integrity:** `readBoundedBody` accumulates chunk
  views and copies once at the end (`:502-531`); a stream that reuses/mutates a
  shared backing buffer across chunks could corrupt the decoded bytes
  (allocation stays bounded; worst case is a shape/JSON rejection). Copying each
  chunk at read time would close it. Direction of trust is hostile-toward-
  importer-server, so cosmetic here.
- **N3 — BOUNDED PROOF GAP:** this client's write/lock paths have only fake-
  server evidence; no live Appwrite acceptance run is possible in scope (no
  cloud mutations). Documented as a known limitation
  (`store-final-api.md:234-238`). Root reports the full client suite green at
  `ad9303b` (385 unit + 135 browser, exit 0 — `task-b-root-latest-
verification.md`), cited, not re-run by me.
